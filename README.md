# MAHJONG LEAGUE

AI雀士たちが日本プロ麻雀連盟の公式ルールで打つ、通年リーグとタイトル戦のシミュレーション（オセロ版 othello-league の麻雀移植）。
ルール判定・点数計算・思考エンジンはすべて自前のPython（標準ライブラリのみ）で動く。点数計算は外部ライブラリ `mahjong`（MIT）とランダムな和了形で突き合わせて検証している。

## 構成
```
mahjong_sim/          麻雀エンジン
  rules.py            ルール設定（既定：日本プロ麻雀連盟 公式ルール）
  tiles.py            牌の表現・ドラ
  shanten.py          向聴数・待ち・受け入れ
  scoring.py          和了判定・役・符・翻・点数
  game.py             対局進行（鳴き・槓・リーチ・フリテン・流局・流し満貫・責任払い・連荘）
  ai.py               思考エンジン（打ち筋9項目＋判断の揺らぎ）
mahjong_league/       リーグとタイトル戦
  individual.py       雀士（打ち筋・技量・年齢・師匠・一門・経歴）
  league.py           鳳凰戦（A〜D）・昇降級・引退・新弟子（師弟制度）
  titles.py           鳳凰位決定戦・麒麟戦・霊亀戦・応龍戦
  tables.py           卓の対局（プロセス並列）と牌譜の記録
  buffs.py / elo.py / names.py / io_utils.py
run_season.py         1期（1年）分を進めるメインスクリプト
run_newcomer_league.py 新人リーグ（投稿キャラ同士のミニリーグ。上位がDリーグに入門）
server/               サイトのサーバー側（PHP＋MySQL）：投稿受付・集計API・データ取り込み
play_demo.py          1半荘を実況表示するデモ
web/                  フロントエンド（静的サイト。data/ のJSONを読むだけでDB不要）
tests/                ルール・点数計算のテスト
```

## ルール
タイトルごとにルールが異なる（`mahjong_sim/rules.py` の `RULESETS` と `TITLE_RULE`）。
| | 持ち点/返し | オカ | ウマ | 一発・裏 | 槓ドラ | 赤ドラ | その他 |
|---|---|---|---|---|---|---|---|
| 鳳凰戦（リーグ・決定戦・新人リーグ） | 30000/30000 | なし | 沈みウマ（浮き1人 +12/−1/−3/−8、2人 +8/+4/−4/−8、3人 +8/+3/+1/−12） | なし | なし | なし | 日本プロ麻雀連盟 公式ルール |
| 麒麟戦 | 25000/30000 | +20 | +30/+10/−10/−30 | あり | あり | 各色1枚 | 数え役満・アガリ止めあり（Mリーグ相当） |
| 霊亀戦 | 30000/30000 | なし | +15/+5/−5/−15 | あり | あり | なし | 数え役満あり（連盟WRC相当） |
| 応龍戦 | 30000 | なし | なし（1着 +1・4着 −1 のみ） | なし | なし | なし | ノーテン罰符なし・和了連荘のみ（101方式）。同点は素点で順位 |

共通：半荘戦、途中流局なし、飛びなし、ダブロンなし（頭ハネ）、喰いタン・後付けあり、役満の複合あり、責任払いあり。
第1季は全タイトル旧ルール（一発・裏・赤なし、定額ウマ +15/+5/−5/−15）で行われた。

## リーグとタイトル
| | 内容 |
|---|---|
| 鳳凰戦 | A12・B16・C20・D28名の通年リーグ（下位ほど多いピラミッド型）。1節4半荘で年間A5節・B4節・C4節・D3節。合計ポイント順。昇降級 A⇔B 2名、B⇔C 3名、C⇔D 4名 |
| 鳳凰位 | Aリーグ上位3名＋前年鳳凰位による決定戦（半荘16回戦）。鳳凰位はAリーグ免除 |
| 麒麟位 | レート上位32名によるシード付きトーナメント（白虎戦に相当） |
| 霊亀位 | 全雀士参加の抽選トーナメント。各卓1半荘、上位2名が勝ち上がり（玄武戦に相当） |
| 応龍位 | 全雀士参加の抽選トーナメント。各卓2半荘の合計（玄武戦に相当） |

トーナメントでは、タイトル保持者と上位リーグの雀士が後の回戦から登場する。前年の保持者は、ベスト4による挑戦者決定戦（上位3名が通過）の勝者3名と決勝を打つ。

## 雀士
- **打ち筋（params）**：牌効率・ドラ・役牌・染め手・タンヤオ・鳴き・リーチ・守備・押しの9項目。
- **技量（talent）**：判断の正確さ。低いほど打牌の評価に揺らぎが入る。麻雀は重みが大きいほど強いわけではないので、実力差は主に技量で表す。若手は伸び、ベテランは緩やかに衰える。
- **ムラ気・年齢バフ・覚醒**：オセロ版と同じ仕組み。
- **入門時の年齢**：新人（新弟子・投稿キャラ）は25〜35歳、覚醒して入門した新人は20〜35歳（オセロ版より幅が広い）。最初の顔ぶれは20〜65歳。
- **師弟制度**：新弟子は既存の雀士に弟子入りし、師匠の打ち筋を受け継ぐ（±15%の変異あり）。強い雀士やタイトル保持者ほど弟子を取りやすい。稀に分岐して新しい一門の開祖になる。
- **引退**：70歳（タイトル保持中は除く）、またはDリーグで2年連続マイナス。

## 実行
```bash
python run_season.py --data-dir data --seasons 1            # 1期（4コアで約10分）
python run_season.py --data-dir data --sections-scale 0.25  # 動作確認用（リーグ戦を短縮）
python play_demo.py --seed 1                                # 1半荘の実況
pip install -r requirements-dev.txt && python -m unittest discover -s tests -v
```
並列数は環境変数 `MAHJONG_WORKERS` で指定する（既定はCPUコア数）。

## フロントエンド（web/）
`web/index.html`・`app.js`・`style.css` と、その隣に置いた `data/` だけで動く静的サイト。画面構成と見た目はオセロ版に合わせている（上段タブ＋サブタブ）。
- **新人**：キャラクリエイト／新人リーグの結果／投稿キャラの歴代記録
- **リーグ**：今季の鳳凰戦リーグ表（所属・年齢・レート、昇降級・新人の印、Dリーグの欠員枠）／一門
- **結果**：鳳凰戦の成績表・鳳凰位決定戦・麒麟戦・霊亀戦・応龍戦（季ごとに◀▶で切替）／表彰／対局記録（名前で検索）
- **タイトル**：現在の保持者／歴代保持者
- **殿堂**：総合ランキング（列で並べ替え）／記録（サーバー集計）／引退者／覚醒者
- **雀士ページ**：打ち筋レーダー、系譜、通算成績（和了率・放銃率・平均打点・立直率など）、対戦相手別成績、タイトル獲得・決勝進出、レート推移、今季の表彰順位、季ごとの成績、最近の対局
- 対局結果・牌譜ビューア（タイトル戦決勝と鳳凰位決定戦の全半荘）
- お気に入り（この端末だけに保存）、新しい季が反映されたときの更新通知

「記録」と「キャラクリエイト」の投稿はサーバー（PHP＋MySQL）が必要。

雀士ごとの詳細（最近の対局・対戦相手別・半荘ごとのレート推移）は `data/players/<id>.json`、季ごとの表彰は `data/awards/season_N.json` に出力する。
過去の季のぶんは `python rebuild_history.py --data-dir data` で対局記録から作り直せる（季は進まない）。

ローカル確認：`mkdir site && cp web/* site/ && cp -r server/. site/ && cp -r data site/ && cd site && php -S localhost:8000`（DB を使うページは `config.php` の設定が必要）

## キャラクリエイトと新人リーグ
1. サイトの「クリエイト」ページで雀士名と打ち筋9項目（合計45まで）を投稿する（`api/submit.php` → MySQL）。
2. GitHub Actions が `admin/export_pending.php` で未処理の投稿を取得し、`run_newcomer_league.py` が新人リーグを開催する。投稿が16名に満たない場合は自動生成の候補で埋める。1人12半荘。
3. 上位のうち、来期のDリーグ欠員数までの投稿キャラが、次の期の開始時に入門する。師匠は自動で選ばれる。技量は入門時に抽選で決まる。
4. `admin/import.php` の取り込みで、投稿のステータス（入門・落選）がサイトに反映される。

## 記録（集計）
`api/stats.php` がMySQLで集計する。
- 個人成績：和了率・放銃率・立直率・ツモ率・平均打点・トップ率・平均着順
- 役満一覧、高打点ランキング、役の出現率、タイトル獲得数、半荘の最高・最低得点

それぞれ通算と期別で見られる。

## サーバー設置（Xserver）
1. MySQLのデータベースとユーザーを作る（サーバーパネル → MySQL設定）。
2. 設置先ディレクトリに `server/config.sample.php` を `config.php` としてコピーし、DB接続情報と `secret_key` を設定する。
3. GitHub のシークレットを登録する。
   - `XSERVER_HOST` / `XSERVER_USER` / `XSERVER_SSH_PORT` / `XSERVER_SSH_KEY`（オセロ版と共通）
   - `MAHJONG_XSERVER_TARGET_DIR`：設置先の絶対パス（末尾 `/`）
4. Actions を手動実行する。サイト一式と data/ が転送され、SSH 経由でサーバー上の `admin/migrate.php`（テーブル作成）と `admin/import.php`（取り込み）が実行される。投稿の取得（`admin/export_pending.php`）も SSH 経由。
   Xserver は海外（GitHub Actions）からの Web アクセスを弾くため、URL を呼ぶ方式は使わない。
   ブラウザから手動で実行したいときは `admin/import.php?key=（config.php の secret_key）` を開く。

`config.php`・`lib.php`・`schema.sql` は `.htaccess` で直接アクセスを拒否している。投稿は1IPあたり1日3件、全体で1日60件まで（`config.php` で変更可）。

## GitHub Actions
`.github/workflows/season.yml` は、毎日 朝6時・昼12時・夜18時ごろ（日本時間の各17分）に1季ずつ進める（手動実行もできる）。オセロ版とは別リポジトリなので、時刻が重なっても互いに待たない。
1. 本戦（`run_season.py`）…冒頭で、前の実行の新人リーグの勝者と新弟子がDリーグに入門する
2. 投稿の取得
3. 新人リーグ（`run_newcomer_league.py`）…本戦で次季の欠員が確定してから開く。勝者は次の実行の本戦の冒頭で入門する（オセロ版と同じ順序）
4. `data/` のコミット・プッシュ
5. Xserver への転送とDB取り込み（シークレット設定時のみ）

Xserver へは、実行ごとに変わる GitHub の実行環境によってはつながらないことがある（同じ実行の中でやり直しても、同じ環境なのでつながらない）。そのため、同じ実行の中では3回だけ試し、つながらなければ実行を「失敗」として終え、**別の実行環境で転送だけをやり直す実行を自動で起こす**（最大3回）。その実行の牌譜（リポジトリに入れていない）は Actions のアーティファクト `kifu-backup`（14日間）に保存され、やり直しの実行が取り出して転送する。
手動実行の `deploy_only` は、季を進めずに転送とDB取り込みだけを行う。`restore_kifu_run_id` に失敗した実行のIDを入れると、その実行の牌譜バックアップも一緒に転送する。

## AIの調整と計測
`python tools/measure_ai.py --games 150 --rule houou` は、リーグの雀士で半荘を多数打ち、局単位の指標を現実のプロの目安（Mリーグの平均：和了率20.6%・放銃率11.0%・立直率24.2%・副露率23.3%・流局率16〜22%）と並べて表示する。技量帯ごとの平均着順も出るので、技量が高いほど強いことも確認できる。
調整用の係数は `mahjong_sim/ai.py` の `TUNE`（`--tune riichi_bias=0.3 dora_scale=2` のように上書きして試せる）。

- 判断のブレ（技量）は、打牌評価の点差が1点未満のことが多いため0〜1点台で使う。ブレを1点にすると流局率が約7pt、3点にすると約15pt増える。
- 標準の設定（鳳凰戦ルール、250半荘）では、和了率20.2%・放銃率13.4%・立直率22.1%・副露率25.3%・流局率19.3%。
- 技量は「判断のブレ」と「他家のリーチ・仕掛けの見落とし」で表す。技量の低い雀士は放銃が増えて着順が下がる（流局は増やさない）。
- 平均和了打点は鳳凰戦ルール（赤・裏・一発なし）で約3,900点。Mリーグ相当のルール（麒麟戦）では約5,400点（目安6,753点）。
- skill 5（2手先まで読む）は計算時間が約7倍で、指標は変わらなかったため使っていない。

## 今後の課題
- **AIの強化（段階導入の第2段階）**：思考部分を Mortal などの強豪AIに差し替える。`MahjongAI` の打牌・鳴き・リーチ判断の入口を差し替え、打ち筋は補正値、技量は揺らぎとして残す想定。
- 平均打点は目安より低い（手作りの価値判断が浅い）。放銃率もやや高い。
