# mahjong-sim

MAHJONG EVOLUTION の学習パイプライン（オセロ版 othello-sim の麻雀移植）。
個性を持つ麻雀AIが4人打ちの卓で世代を重ね、いずれ最強の壁（タイトルホルダー）に挑む。

オセロ版と同じく外部エンジンへの依存はなく、ルール判定・点数計算・思考はすべて自前のPython（標準ライブラリのみ）で完結する。

## 構成
```
mahjong_sim/
  tiles.py        牌の表現（34種×4枚）・ドラ
  shanten.py      向聴数・待ち・受け入れ計算（通常手／七対子／国士無双）
  scoring.py      和了判定・役・符・翻・点数計算
  game.py         4人打ちの対局進行（ツモ・打牌・リーチ・ポン/チー・ロン・流局・連荘・終局）
  ai.py           思考エンジン（評価関数の重みが個性。skill でベンチマークの強さを調整）
  individual.py   個体定義
  elo.py          4人打ち用Eloレーティング（全ペアの1対1に分解）
  evolution.py    進化ロジック（スイス方式4人卓トーナメント・変異・移民交配・流派保護・タイトル挑戦）
  family_names.py 血統名生成
  io_utils.py     チェックポイント読み書き
  play.py         対局処理（個体卓・ベンチマーク卓・タイトル戦卓）
run_evolution.py  メイン実行スクリプト
play_demo.py      1局分を実況表示するデモ
tests/            ルール・点数計算のテスト
```

## 個体の「個性」（params, 0.5〜10）
| キー | 意味 |
|---|---|
| speed_weight | 牌効率（受け入れ枚数）重視 |
| dora_weight | ドラを大切にする |
| yakuhai_weight | 役牌を大切にする |
| flush_weight | 染め手（混一色・清一色）志向 |
| tanyao_weight | 断么九志向 |
| call_weight | 鳴きの積極性 |
| riichi_weight | 即リーチの積極性（低いとダマテンを好む） |
| defense_weight | 守備意識（危険牌を避ける） |
| push_weight | 押し度胸（手が良いときは守備を緩める） |

打牌は「攻撃（向聴数・受け入れ）＋打点（ドラ・役牌・染め手・タンヤオ）−守備（現物・筋・字牌の見え方による危険度）」が最大の牌を選ぶ。

## 設計の要点（オセロ版からの対応）
| オセロ版 | 麻雀版 |
|---|---|
| 1対1のスイス方式 | 成績順に4人ずつ卓を組むスイス方式（同卓の重複はなるべく回避） |
| 勝敗でElo更新 | 着順を全ペアの勝敗に分解してElo更新（K/3ずつ） |
| スコア＝勝ち点 | スコア＝ウマ・オカ込みのポイント（25000持ち30000返し、ウマ+30/+10/-10/-30） |
| 温度計＝探索深さ | 温度計＝ベンチマークAIの思考レベル（1〜4）。首位が固定AI3人の卓に入り、着順スコア（1着=1.0〜4着=0）で測る |
| タイトルホルダー＝深さ7 | タイトルホルダー＝レベル5（2段先の受け入れまで読む）。平均着順2.0以下で奪取 |

その他（無性生殖・移民・交配・恒久保証・猶予期間など）はオセロ版と同じ仕組み。

ベンチマークのレベル:
1. 自分の手牌だけで受け入れを数える／守備なし／鳴かない／常に即リーチ
2. 見えている牌を考慮／現物だけで守る／役牌だけ鳴く
3. 筋・字牌の見え方で危険度を測る／タンヤオ・染め手でも鳴く／押し引きあり
4. ダマテン判断あり（個体と同じ思考精度）
5. 2段先の受け入れ（好形変化）まで読む（タイトルホルダー専用）

## ローカル実行
```bash
# 進化（東風戦・16個体・4ラウンド）
python run_evolution.py --data-dir data --generations 3 \
  --population-size 16 --swiss-rounds 4 --game-length east --benchmark-games 6

# 1局観戦
python play_demo.py --level 4 --seed 1

# テスト
python -m unittest discover -s tests -v
```

## 出力データ（data/）
- `individuals.json` … 全個体（params, Elo, 対局履歴, 血統）
- `matches.json` … 対局ログ。卓の席順・最終点数・着順・ポイントと、各局の結果（和了者・放銃者・役・符・翻・点数移動・流局時の聴牌者）。打牌の全履歴は容量の都合で保存しない
- `training_state.json` … ベンチマークレベル・温度計履歴・現役個体・タイトル奪取記録・流派保護情報

## GitHub Actions
`.github/workflows/evolve.yml` が毎日（UTC 21:00）または手動実行で世代を進め、1世代ごとに data/ をコミット・プッシュする。
シークレット `XSERVER_HOST` と `MAHJONG_XSERVER_TARGET_DIR` が設定されている場合のみ、オセロ版と同様に Xserver へ scp し、`MAHJONG_IMPORT_URL` があればインポートURLを叩く。

## 既知の制約（今後の課題）
- ルールの簡略化: 赤ドラなし・カンなし（槓ドラ・嶺上開花・槍槓・四槓子なし）、途中流局なし、流し満貫なし、ダブロンなし（頭ハネ）、西入なし、喰い替えは同じ牌のみ禁止
- 数え役満あり、役満の複合は加算するが四暗刻単騎などのダブル役満扱いはしない
- 麻雀は運の要素が大きいため、温度計の数局ではブレが大きい。`--benchmark-games` を増やすほど安定する
- タイトルホルダーは暫定的に自前AIの最高精度版で代用（将来的に外部の強豪AIへ差し替え予定）
